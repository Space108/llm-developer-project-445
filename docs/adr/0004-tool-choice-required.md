# 0004. Принудительный tool_choice у write-агентов

## Контекст

Tariff-агент с read+prepare инструментами часто вызывал `get_my_profile` и дальше отвечал текстом без `prepare_*` — карточки не было. Tickets при эскалации без карточки иногда уточнял вместо `create_ticket`.

## Решение

- У агента `tariff` с write-доступом в каталоге только `prepare_*` (чтение текущего тарифа делает сам action-сервис).
- `ModelSettings(tool_choice="required")` для `tariff` (с prepare) и `tickets`.
- Оркестратор дописывает в task реплику абонента и «сразу вызови инструмент».
- Эскалация «оператор» без живой карточки идёт в `_escalate` напрямую (classify уже помечает operator).

## Альтернативы

- Оставить read-инструменты и надеяться на промпт.
- Жёсткий `tool_choice="prepare_tariff_change"` (ломает услуги/контакты).
- Пост-проверка «не было prepare → повтор хода» в оркестраторе.

## Когда пересмотреть

Если локальная модель начнёт стабильно соблюдать «сначала prepare»; или SDK/провайдер иначе обрабатывает `tool_choice` с несколькими prepare_*.
